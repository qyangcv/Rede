# 清理 Rede 代码

目标是降低后续维护成本，同时保持现有用户行为、调用契约和已存数据兼容。遵守项目的 AGENTS.md。

## 确定范围

- 用户指定模块或平台时，从该范围的入口往下追踪。要求清理整个代码库时，先梳理 macOS、iOS、Shared 及阅读器 Web 资源的关系。
- 区分审查范围和可编辑文件。用户未点名文件时，只给带 `file:line` 的建议；明确要求修改并点名文件时，只在点名文件内实施。若一项重构还需改动其他文件，列出完整范围，避免只完成一半。
- 用只读 Git 命令了解已有改动，保留用户正在进行的工作。

## 判断哪些改动值得做

- 沿真实调用路径寻找重复业务规则、可消除的状态、职责混杂的模块，以及在高频路径上反复执行的工作。每个候选项都要说明它今天造成了什么具体成本。
- 删除疑似死代码前，检查两个平台的入口、Swift 与 JavaScript 之间按名称调用的接口、资源加载路径及持久化用途。单次文本搜索没有命中，不足以证明可以删除。
- 合并重复逻辑前，确认两处表达的是同一条规则，且应当一起变化。保留各平台原生交互和容器；已有第二个平台调用时，再考虑移入 `Shared/`。
- 拆分大文件时，以职责、调用方或状态所有权为界。行数本身不是拆分理由。涉及 CloudKit 模型时，把现有记录可读、生产 schema 只增不减作为兼容条件。
- 性能优化要指出具体操作和触发频率。可以从代码证明减少了几次解析、查询或渲染；要声称用户可感知的提速，则需用同一输入做前后测量。

## 实施与验证

把候选项拆成可独立审查和验证的小改动，优先处理收益明确、证据充分的项。每项写清位置、当前行为、建议改法和验证方法。涉及依赖升级、框架迁移或可观察行为变化时，单列为后续任务。

实施获准的改动后，检查 diff，运行受影响平台的构建和相关现有测试。共享逻辑覆盖两个平台；涉及阅读位置恢复、中文排版或同步时，按受影响的用户操作验证。报告实际运行的检查及结果，区分已验证和仍待验证的行为。没有值得做的改动时，直接说明。
